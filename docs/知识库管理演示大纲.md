## 一、怎么管理（How）—— 2 页【重点】

### 幻灯片 1/2：写 / 读 双线闭环

核心公式（来自 MSDD 文档与知识库设计方案）：
> **知识库 = 规约文档（MSDD 命令驱动）+ Wiki（LLM-Wiki 驱动）** 双层架构

闭环示意图（方正一圈：四状态、四箭头、零交叉）：

```text
代码 ──────① 提炼规约──────▶ 规约文档
 ▲                             │
 │                             │
 │ ④ 编码                       │ ② 入库(Ingest · llm-wiki)
 │                             │
 │                             ▼
功能开发 ◀──③ 搜索知识(obsidian-mcp-pro)── 知识库(Wiki)
```

- **写线** = 上边 + 右边：代码 → 规约文档 → 入库（`llm-wiki` 负责）
- **读线** = 下边：搜索知识（`obsidian-mcp-pro` 负责，功能开发时从知识库搜）
- **闭环** = 左边：功能开发产出代码，回到起点；每转一圈，规约与知识库更新一次 → 复利

**闭环逻辑（一句话）**：
> 写线把「代码/原始文档 → 规约文档 → 知识库」沉淀进去；读线在功能开发时从知识库做需求澄清、方案设计、需求验证；编码完毕并验证通过后更新规约文档、同步更新知识库——回到写线，形成闭环。


---

### 幻灯片 2/2：三条管理规范

**① 知识库跟着代码（同仓同源）**
- 依据：规约文档随代码放 `docs/`、知识库 `wiki/` 同仓 → 同源、同版本、同生命周期
- 拉代码即得知识；随代码评审 / Lint；`.msdd/` 过程数据不入库

**② 规则定义（规范体系 · 单一来源 `knowledge-management.mdc`）**
- 查询分流（不得跳级）：🥇 Wiki 优先 → 🥈 CodeGraph → 🥉 传统搜索兜底
- 读写双通道：写 → `llm-wiki` subagent（草稿确认后写）；读 → `obsidian-mcp-pro` 直连（即时）
- 总结沉淀：草稿确认后再写 `docs/summary/` 或 `wiki/syntheses/`
- Wiki 约定：双链 `[[页面名]]` + 前缀 `src-/ent-/con-/cmp-/syn-` + `index.md`/`log.md`

**③ 多知识库处理（白名单 + 显式路由 + 路径校验）**
- 每库 = 一个 Obsidian vault，根路径在 `OBSIDIAN_ALLOWED_ROOTS` 白名单
- 查询显式传 `projectPath`，先用 `get_vault_stats` 校验；vault 清单见 `工程组织规范.mdc`

## 二、为什么需要 + 是什么（Why & What · 1 页）

**为什么需要（Why）：有了规约文档，为什么还要知识库**
- 规约文档是"原材料"：按功能/模块切分（需求/设计/调试），概念散落多份、彼此孤立，AI 每次都得重新通读才能理解
- 知识库是"已结构化的理解"：把对文档知识点的理解提炼成 Wiki 概念页（`con-*`）+ `[[双链]]` 聚合枢纽，一次理解、跨文档复用
- 关键收益：AI 不必每次重新理解；理解沉淀一次、复用多次，随 Ingest/Lint 持续**复利**增长

**知识库是什么（What）**
- 一句话：知识库 = 规约文档之上的"已结构化理解层"（即 Wiki 知识积累层），用 `[[双链]]` 把散落各文档的知识概念**串联**成可复用的知识网络
- 构成：五类页（`src-/ent-/con-/cmp-/syn-`）+ `[[双链]]` 聚合枢纽 + `index.md` 导航 / `log.md` 日志 —— **直观展示：配 Obsidian 知识点联系图（节点=知识页，连线=双链）**
- 与文件库区别：文件库存"文档"，知识库存"理解"——有结构 / 有链接 / 可语义检索（Wiki First）/ 随 Ingest·Lint 持续复利 ≠ 网盘

**基本工具**
- 知识库搭建与维护：`llm-wiki` —— 由**大模型负责把散落的知识点串联**成网络（Ingest 录入 + Lint 健康检查）
- 知识库读取：`obsidian-mcp-pro` —— **直接通过工具（非 LLM）搜索**，即时返回、不经大模型中转
